# ChatGPT conversation workspace

The isolated-world page adapter activates only on supported `https://chatgpt.com` conversation pages. A single chat keeps the normal page layout. Opening a second conversation from the sidebar reveals an in-page tab row; selecting a conversation already open focuses its existing tab. New chat reuses an untouched empty tab. Menus offer split view, closing, reopening and moving a chat to a window. The row inherits website typography and theme. Chat tabs and ordinary browser tabs support native hold-and-drag tear-off, with a menu alternative for accessibility. The isolated DOM adapter reports tab hit regions; UIKit owns the chat-tab drag session and the desktop validates a process-local transfer token.

Each conversation retains a real WKWebView using the owning profile's website data store. A workspace host presents the selected page and a clipped second native web view in the layout slot reported by the DOM adapter. The header and tab row stay in the webpage. Split view needs 760 CSS pixels in the conversation area; each pane keeps 360 pixels and its own composer and scrolling. Shrinking collapses to the focused chat while keeping other tabs. Browser commands follow the focused page.

Transfers move the existing page object rather than loading a copy of its URL. The new window enters normal window, Spaces, Dock and Mission Control management. Clicking an app-bar item with multiple windows opens a chooser with switch, minimise and close actions; pinned web apps retain their grouping and stable app names. The Window menu lists every window and restores minimised windows when selected. Closing a single-tab window through a tear-off gesture just moves that window.

Only links, ordering and layout are saved under the existing normal-browser restoration policy. Titles, messages, drafts and response bodies are not serialized. Private profiles stay memory-only; cookie stores are not mixed. Draft/generation flags cross the native bridge as booleans. Closing a chat with a draft or ongoing response requires confirmation; inactive workspaces with these flags are not voluntarily hibernated. WebKit or OS process termination can still lose unsent page state.

The adapter uses semantic landmarks and supported conversation routes. If a layout is unrecognised, normal website navigation remains available. Authentication and unsupported-page navigation leave the workspace. The site-only ChatGPT Chat Tabs option can disable integration. Page controls use a separate JavaScript content world, exact origin checks and a main-frame-only message handler; no account tokens or cookies are read. Browser-tab drag tokens are process-local.

Validation includes Swift state tests and headless DOM fixtures for route/origin restrictions, activation, deduplication, draft protection, split layout, selection, menus, theming cleanup and privacy. The GitHub workflow runs core/DOM checks and compiles/packages the actual arm64 device application; it does not run simulator or preview jobs. DOM fixtures cannot prove compatibility with the current authenticated ChatGPT website. Physical drag, keyboard, split geometry and live-site layout must also be checked on an iPad after installing the IPA.
