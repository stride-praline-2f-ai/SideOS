# Built-in JIT setup

Open **SideOS Settings → Built-in JIT** for the guided screen. Its controls use the
existing built-in coordinator, not a second debugger implementation.

JIT means an app can run code it generates while you use it. Most apps do not
need it, and SideInstaller should open without enabling it. The in-app guide has
six expandable steps; use **Next step** to continue. Its setup checkmarks reflect
the provider, pairing record and current preparation state, rather than whether
you have read a step.

1. Choose **Use built-in JIT**. This selects the provider but does not start JIT.
2. Enable Developer Mode in iOS Settings when required, restart as prompted, and
   connect the supported LocalDevVPN connection. A generic internet VPN does not
   replace that device connection.
   Developer Mode is under **Settings → Privacy & Security → Developer Mode**.
   Confirm it again after the requested restart. Open LocalDevVPN and connect
   its device tunnel; SideOS's tutorial has a shortcut. If it is not installed,
   follow the supported-tools link in the official guide. SideOS cannot enable
   Developer Mode or install a VPN configuration automatically.
3. Open **SideInstaller → Tools → Pairing** to pair this physical device. The
   built-in record is shared automatically. If SideInstaller cannot open, use
   **Open pairing and preparation controls → Import pairing file** with a record
   generated by your own trusted computer for this device. Never share it.
   Follow SideInstaller's on-screen pairing PIN/Settings prompts and keep the
   app open until completion. The tutorial summary should then show **Pairing
   record available**. It does not require exporting or sending that record.
4. In those controls, choose the available pairing source and tap **Prepare
   device**. Keep SideOS open and wait for the connectivity/DDI result. This
   readiness is limited to the current host session and pairing record.
5. Mark the desired guest as needing JIT in LiveContainer app settings and launch
   it from SideOS. Each app still needs a separate attach/script result for its
   LiveProcess PID. A “Device prepared” label alone is not JIT success.

Keep Classic/Compatibility Mode off for the built-in LiveProcess route. Helper
and RAM-donor apps currently require upstream Classic Mode with an appropriate
external provider. On iOS 26+, JIT does not replace required JIT-less signing.

If preparation fails, check correct-device pairing, LocalDevVPN, supported OS,
app-group access, LiveProcess/SIJITHelper and retained get-task-allow during signing.
Close the guest before retrying. Reset the DDI cache only for download/mount
troubleshooting; it does not replace pairing. Never attach a debugger to the
SideOS UI process. Use the [official JIT guide](https://livecontainer.github.io/docs/guides/jit-support)
for provider-specific requirements.

The final tutorial step explains repetition: a new guest process needs a new
JIT operation; reconnect and prepare after a restart, connection change or expired
session. Re-pair only for an invalid/wrong-device record. The troubleshooting
disclosure separates missing pairing, connection failures, image download/mount
failures and an app that fails after preparation. Do not reset the image cache
for unrelated errors. Pairing and signing inside SideOS do not provide isolation
from malicious hosted apps; only run IPAs you trust.
